# Bili2Douyin · B站弹幕链接抖音

> Overlay Bilibili live danmaku on Douyin live streams, with adjustable time-offset sync.
>
> 在抖音直播画面里叠加显示 B 站直播间的弹幕，手动调节延迟即可让两边的弹幕节奏对齐。

基本不维护，自用

在抖音直播画面里叠加显示 B 站某个直播间的弹幕，并可以手动设置延迟，让两边的弹幕节奏对上。

- 弹幕直接飞在抖音直播画面里（默认），也可以切换成右侧列表，或两者同时显示
- 和 B 站网页一致的完整弹幕流：认证包会带上 B 站网页同款的 `buvid` 匿名设备 ID，避免服务器只下发一部分弹幕
- 延迟可调（0 ~ 600 秒，滑条 0 ~ 120 秒，也可直接输入秒数），用来补偿两个直播间的推流延迟差
- 弹幕样式可调：字体（系统默认 / 微软雅黑 / 黑体 / 宋体 / 楷体 / 思源黑体 / 苹方）、滚动时长（4 ~ 20 秒）、不透明度（20% ~ 100%）、阴影（无 / 弱 / 中 / 强）、颜色（跟随 B 站 / 统一白色 / 自定义）、密度（10% ~ 100%）、显示区域（全屏 / 上半屏 / 上四分之一）
- 连接过的 B 站直播间会自动保存（带房间标题），点一下就能快速切换，可单独删除
- 不丢弃弹幕：同一批到达的弹幕会被平滑摊开、按先后顺序逐条出现，不会一波一波地弹出来，也不会在右侧排成一条竖线
- 同屏到上限（900 条）时优先保留新弹幕、提前清掉最老的，不会出现“看着看着新弹幕不来了”
- 排队缓冲约 0.1 ~ 1 秒（按积压自适应），不会出现十几秒的延迟
- 链路自动保活：页面每 15 秒给连接宿主发一次心跳；长时间没有数据会自动重连，iframe 被页面移除会自动重建
- 控制条可拖动、可缩放、可收起、可隐藏；画面弹幕字号、面板不透明度可调
- 断线自动重连；刷新抖音页面后自动恢复房间号和延迟
- 安装或更新扩展后，会自动补注入到已经打开的抖音直播页

## 安装

适用于 Chrome / Edge 等 Chromium 内核浏览器（需要 Chrome 116+）。

### 方式一：下载 Release 压缩包（推荐给普通用户）

1. 打开 [Releases](https://github.com/hz121315/Bili2Douyin/releases) 页面，下载最新的 `Bili2Douyin-vX.Y.Z.zip`
2. 解压到任意目录（**不要直接在压缩包里加载**，需要先解压）
3. 打开 `chrome://extensions`（Edge 是 `edge://extensions`）
4. 打开右上角的「开发者模式」
5. 点击「加载已解压的扩展程序」，选择**解压后包含 `manifest.json` 的那个目录**
6. 打开任意抖音直播间，例如 `https://live.douyin.com/xxxx`
   （插件只在 `live.douyin.com` 的直播页生效）

> 压缩包里已经包含 `manifest.json`、运行代码、`README.md`、`LICENSE` 和 `PRIVACY.md`，没有开发文件，可以直接用于 Chrome 应用商店提交。

### 方式二：从源码加载（开发者）

```bash
git clone https://github.com/hz121315/Bili2Douyin.git
```

1. 打开 `chrome://extensions`（Edge 是 `edge://extensions`）
2. 打开右上角的「开发者模式」
3. 点击「加载已解压的扩展程序」，选择仓库目录
4. 打开任意抖音直播间

> 如果你是**更新**这个扩展：点扩展卡片上的「重新加载」，然后刷新一次已经打开的抖音直播页。之后新打开的直播页不需要再手动刷新。

## 使用

1. 抖音直播页右上角会出现「B站弹幕」控制条
2. 点控制条右上角的 ⚙，填入 B 站直播间号（`6` 或完整链接 `https://live.bilibili.com/6?...` 都可以），点「连接」
3. 连接成功后状态变成「已连接」，B 站弹幕就会飞过抖音直播画面

默认是「画面内」模式：控制条只保留标题、延迟滑条和状态，弹幕画在视频上。设置里的「弹幕显示位置」可以改成「右侧列表」或「两者」。

### 画面弹幕设置

在 ⚙ 里可以调：

- **字号**：画面内弹幕的字体大小，提供 16 / 20 / 24 / 30 / 36 几个常用快捷字号，也可以用滑条在 14 ~ 40 之间微调
- **不透明度**：画面内弹幕的透明度，20% ~ 100%（默认 100%）
- **阴影**：文字阴影强度，无 / 弱 / 中 / 强（默认中）
- **字体**：画面内弹幕使用的字体，可选系统默认 / 微软雅黑 / 黑体 / 宋体 / 楷体 / 思源黑体 / 苹方（按系统已安装字体生效）
- **滚动时长**：一条弹幕横穿画面要多久，4 ~ 20 秒，越大越慢（默认 12 秒）
- **颜色**：跟随 B 站 / 统一白色 / 自定义（选自定义后可取色）
- **密度**：10% ~ 100%，默认 100%（全部显示）；调低会随机少显示一部分，缓解刷屏
- **显示区域**：全屏 / 上半屏 / 上四分之一，只在这些区域里分配弹道

设置最下方的「诊断」会显示：

```
弹幕统计：网络收到 128 · 画面显示 128 · 丢弃 0 · 队列 0 · 缓冲 0.1s（峰值 0.4s）
```

- **网络收到**：WebSocket 实际收到并交给弹幕层的条数
- **画面显示**：真正上屏的条数（100% 密度时应该等于网络收到）
- **丢弃**：只有调低密度、或同屏超过 800 条时才会增加
- **队列 / 缓冲**：排队中的条数和排队时间，正常情况下缓冲在 0.1 ~ 1 秒
- **链路**：`WS 在线 · 2 秒前有数据` 表示长连接健康；如果显示离线或很久没有数据，插件会自动重连
- **分时**：最近每分钟的 `收到/显示/丢`，保留 10 分钟。出问题时对比这几列就能判断是网络没收到，还是显示被限制
- 注意这里的「缓冲」是插件内部排队时间，不包含你设置的「延迟」

### 用延迟对齐两个直播间

「延迟」表示这条 B 站弹幕要晚多少秒才显示。

- 抖音画面比 B 站**慢** N 秒（B 站先出现某个画面，抖音稍后才有）：把延迟调到 **N 秒**
- 抖音画面比 B 站**快**：延迟调到 0（实时弹幕无法提前显示，延迟 0 就是最快）

校准方法：找一个能同时看到的瞬间（主播说某句话、某个特效出现），看抖音画面比 B 站弹幕晚多久，就填多少秒。调整延迟时控制条会显示「缓冲 N 条」，表示这段时间的弹幕正在排队；调低延迟后排队弹幕会立刻补上。

延迟可以这样调：

- 拖动底部滑条（0.5 秒步进）
- 点 `-1s` / `-0.5s` / `+0.5s` / `+1s`
- 键盘 `Alt+[` / `Alt+]` 微调 0.2 秒
- 设置里直接输入秒数（支持小数，最高 600 秒）
- 浏览器工具栏图标里也有同样的快捷调节

## 常见问题

**状态一直「重新连接中」，提示 WebSocket 连接断开（1006）**

先看设置里「诊断」的「连接方式」：

- **扩展 iframe**：这是正常的主通道，长连接跑在页面里的扩展 iframe 中
- **后台 Service Worker**：说明扩展 iframe 没能加载，用了回退通道。360 极速浏览器X 等浏览器会断开后台 Service Worker 里的 WebSocket，请确认扩展版本是 2.3.0 以上并刷新抖音页面；仍不行就改用 Edge / Chrome

再看「Token」和「上次错误」：

- `Token：空`：没拿到 token，多半是 B 站接口被风控；插件会自动改用备用接口，仍失败时请把诊断发我
- 1006 且「上次错误」里带「正在改用备用接口」：说明第一次拿到的 token 认证不匹配，插件会自动用匿名接口重新取 token 重试
- 仍然失败：点「复制诊断」把内容发我

**弹幕比 B 站网页少**

2.0.0 已修复：B 站弹幕服务器会按认证参数分流，不带 `buvid` 的连接只收到一部分弹幕。现在认证包带上从 `finger/spi` 获取的匿名设备 ID，弹幕量与 B 站网页一致（同一时段实测 98 vs 90）。不需要登录 B 站。

如果仍有明显缺失，看诊断里的 `分时（收到/显示/丢）`：`收到` 明显少于 B 站网页就是连接侧，`显示` 小于 `收到` 才是显示侧。

**填了链接、点了连接，画面里还是没有弹幕**

按顺序排查：

1. 看控制条下方是否有红色提示条，例如「房间信息获取失败」「弹幕服务器认证失败」。提示条上有「重试」按钮
2. 如果状态一直显示「重新连接中，N 秒后重试」，点 ⚙ 看设置最下方的「诊断」，重点看这几行：
   - `接口`：`getDanmuInfo` 是官方接口，`getConf` 是备用接口（官方接口被风控时会自动切到备用）
   - `服务器`：连的是哪台弹幕服务器（备用接口会优先给 443 端口的线路）
   - `上次错误`：失败阶段和具体错误码
   - 点「复制诊断」可以把这些信息复制出来
3. 确认 B 站房间正在直播且有人在说话（冷清的房间可能十几秒才有一条）
4. 如果是刚安装/更新扩展，刷新一次抖音直播页
5. 如果提示认证失败，先在浏览器里打开并登录一次 [live.bilibili.com](https://live.bilibili.com/)，再回来点「重试」
6. 如果提示「无法访问 B 站接口（网络错误）」，检查代理 / VPN / 广告拦截插件是否拦了 `api.live.bilibili.com` 或 `*.chat.bilibili.com`

插件会先尝试官方接口 `getDanmuInfo`；如果被 B 站风控拒绝（-352）或请求失败，会自动改用旧接口 `getConf` 拿 token（这个接口不需要签名和 Referer，并且返回 443 端口的服务器），再连不上才会进入重试循环。

**右侧列表有弹幕，但画面里没有**

说明没定位到直播 `<video>`（页面结构变化、或者视频还没加载出来）。这种情况下插件会自动改用右侧列表；也可以稍等几秒、或刷新页面后重试。设置里的「诊断」会显示「视频：已定位 / 未找到」。

**显示「已连接（房间未开播）」**

房间号是对的，但主播没开播，开播后弹幕会自动出现。

**B 站昵称显示成 `阿***`**

这是 B 站弹幕接口本身返回的脱敏昵称，不是插件改的。

**画面弹幕挡住了抖音的礼物/提示**

弹幕层只覆盖视频区域且不接收鼠标事件，不会影响点击。介意的话可以把字号调小，或切到「右侧列表」模式。

## 工作原理

- 抖音页面里的内容脚本会创建一个隐藏的扩展 iframe（`frame.html`），由它解析房间号、用 WBI 签名请求 `getDanmuInfo`（失败时自动改用 `getConf`）拿到 token 和弹幕服务器列表，并建立 WebSocket 长连接
- 请求 B 站接口时不带登录 Cookie（`credentials: 'omit'`）：弹幕认证包固定用匿名 `uid: 0`，如果 token 是按登录账号签发的，两者不匹配会被服务器直接断开（1006）；万一 token 仍不可用，会自动改用 `getConf` 重新取一个匿名 token 重试
- 认证包会额外带上从 `finger/spi` 获取的匿名设备 ID `buvid`。实测不带 buvid 时 B 站服务器只下发一小部分弹幕（同一 40 秒内 19 条 vs 45 条，和 B 站网页对比是 90 vs 98），带上后弹幕量与 B 站网页一致；这一步不需要登录
- 长连接运行在扩展页面环境里，不受后台 Service Worker 被浏览器挂起/断开的影响（360 极速浏览器X 等浏览器会在后台 Service Worker 里立刻断开 WebSocket）
- 弹幕通过 postMessage 回到内容脚本，进入本地队列，按「到达时间 + 延迟」释放
- 释放后交给画面弹幕层：定位页面里面积最大的 `<video>`（自动扣除 `object-fit: contain` 的黑边），按行分配轨道，从右向左飞行
- 如果浏览器不允许嵌入扩展 iframe，会自动回退到后台端口 + offscreen 文档 / Service Worker 直连
- B 站接口要求 Referer，扩展后台请求默认没有，所以用 `declarativeNetRequest` 规则给发往 `*.bilibili.com` 的扩展请求补上 `Referer: https://live.bilibili.com/`
- 扩展安装/更新时，后台会用 `chrome.scripting` 给已经打开的抖音直播页补注入最新的内容脚本

权限说明：`storage`（保存设置）、`declarativeNetRequest`（补 Referer）、`scripting`（给已打开页面补注入）、`offscreen`（无 iframe 时的回退方案）、以及 `https://*.bilibili.com/*` 和 `https://live.douyin.com/*` 主机权限。不收集、不上传任何数据。

## 隐私

- 不收集、不上传任何数据，没有账号系统
- 只在本地 `chrome.storage` 保存房间号、延迟、颜色、字号等设置
- 读取弹幕时使用匿名身份（`uid: 0`，不带登录 Cookie），不会读取你的 B 站账号信息
- 不申请 `cookies` 权限，不读取登录态；目前也不包含“发送弹幕”功能
- `tools/`、`dev/` 里的脚本只在本机运行，不会把数据发到外部服务器
- 仓库内的示例房间号（`6` / `3044248` / `7734200`）都是公开的中性示例
- 完整说明见 [PRIVACY.md](PRIVACY.md)

## 文件结构

```
manifest.json          扩展清单（MV3）
rules.json             declarativeNetRequest：给 B 站请求补 Referer
background.js          后台：房间订阅、端口分发、脚本补注入
frame.html/.js         页面内隐藏的扩展 iframe：承载弹幕 WebSocket（主通道）
offscreen.html/.js     offscreen 文档回退通道
danmaku-layer.js       画面内弹幕层（定位视频、弹道、飞行动画、SC）
content.js/.css        控制条、设置、队列与延迟逻辑
popup.html/.js         工具栏弹窗：连接、延迟微调、显示/隐藏面板
lib/bilibili.js        房间解析、WBI 签名、数据包编解码、弹幕提取
lib/danmaku-client.js  弹幕连接客户端（心跳、重连、服务器轮换、诊断信息）
lib/md5.js             MD5（WBI 签名用）
icons/                 扩展图标
dev/                   开发自测页
tools/probe.mjs        命令行探针：验证 B 站协议链路
tools/make-icons.mjs   重新生成图标
```

## 开发自测

1. 命令行验证 B 站链路（不经过浏览器扩展）：

   ```bash
   node tools/probe.mjs 7734200 15
   ```

2. 在浏览器里验证控制条：加载扩展后打开

   ```
   chrome-extension://<扩展ID>/dev/test.html?room=3044248
   ```

3. 验证画面内弹幕：直接打开一个真实的 `live.douyin.com` 直播间，通过控制条连接即可；设置里的「诊断」会显示视频区域的定位结果。

## 已知限制

- 只显示文字弹幕和醒目留言（SC），不显示礼物、进场、舰队等消息。B 站网页右侧聊天面板里的「XX 进入直播间」「投喂」等不是弹幕，所以看起来会比面板少
- 不支持发送弹幕
- 为了让同一批到达的弹幕看起来连续，会有一个约 0.1 ~ 1 秒的排队缓冲（高密度时自适应，不会堆积到十几秒）
- 极高密度的直播间（同一瞬间几十条）为了保证不丢弹幕，相邻弹幕可能会有轻微重叠；可以调小字号、调低密度或改用右侧列表
- 延迟功能是「延后显示」，无法让弹幕比 B 站实际到达更早出现
- 如果抖音的原生全屏把 `<video>` 本身设为全屏元素（而不是播放器容器），网页元素无法叠加在上面，弹幕会暂时不可见；使用抖音播放器自带的全屏按钮通常没问题
- 依赖 B 站非公开接口，接口或风控策略变化时可能需要更新
